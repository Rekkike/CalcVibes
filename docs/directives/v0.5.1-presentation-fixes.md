## Task G — The deck design system (the headline)

Implement the design conventions of record as CSS custom properties applied to the presentation layer (screen), with the print and PDF surfaces following the same system:

- Type: one professional sans family via a token (--font): a system-safe stack (for example Inter, Segoe UI, system-ui, -apple-system, sans-serif). No external font fetches — offline discipline; the desktop packaging at v1.0 must not break.
- Color: tokens --accent (one accent of record, suggestion #6366f1 — final choice may adapt to the family), --ink (near-black), --muted (gray scale for secondary text), --surface (slide background), page background neutral. One accent only, used where it encodes meaning. Data-ink discipline: no borders, gridlines, or decoration that carry no data.
- Layout: one consistent content width (suggestion max 56rem), a consistent spacing scale via tokens, generous whitespace, slide content vertically composed with the title dominant.
- Slide chrome: a quiet header (project name, muted, top) and footer ("slide n of 5" plus the provenance line "Generated from the live model — <project>", muted, small) on every slide; consistent across screen, print, and PDF.
- Figures: each figure a consistent row — label left, value right-aligned (display-rounded strings unchanged), disclosure in smaller muted type on the same row.
- Disclosures: styled to inform, not alarm — muted, smaller; the ambiguity warning stays visually distinct but calm; nothing alarm-red for informational caveats.
- Titles: slide 1 an h1 at display scale; slides 2-5 h2 action titles at one consistent scale. The title and figure STRINGS are unchanged — EX-1 and EX-2 pins remain byte-valid; styling changes presentation only.
- Navigation: keyboard and the on-screen Previous/Next preserved.
- Emotional register: confidence without exaggeration; no gradients-as-decoration, no shadows-for-drama, no 3-D.

Structural pins (so defaults cannot pass): the stylesheet defines the token custom properties; figure values right-aligned; the composition bar accent-token-driven; header and footer chrome rendered on every slide; disclosures muted. Paper rendering and overall aesthetics remain the user's walkthrough — this pass ships, the walkthrough grades — but the structural pins must exist and each must be red-provable (remove a token, break the alignment class, reintroduce the second color, hide the chrome — each flip goes red). Component-contract tests stay in isolation per the standing pattern.
