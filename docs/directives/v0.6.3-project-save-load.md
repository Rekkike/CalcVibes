## Preamble — the design of record

- THE PROJECT FILE IS THE ENGINE SCHEMA: a UTF-8 JSON document `{ fileKind, fileVersion, project, settings }` where `project` is the ModelInputs object verbatim and `settings` is the project settings block. No timestamps, no computed results (results derive from inputs; determinism: a re-save of a loaded file is byte-identical).
- THE SETTINGS BLOCK CLOSES THE THREE STANDING TRANSIENT-STATE CARRIED ITEMS: `startYear` (the v0.3.1 observation 4, "wire at v1.0"), `entryUnit` (the v0.5.3 observation, fromFile not extended), and the user-supplied scenario lists (the v0.5.2 standing item). All three travel in the file.
- THE XLSX EXPORT REMAINS PRESENTATION-ONLY BY DESIGN; XLSX import is rejected of record (a lossy parse of a presentation document). The template-project.json demo asset is NOT a project file and refuses by kind (pinned).
- THE COLLECT-ALL CONTRACT: structural corruption refuses with a named error, never a silent fallback to blank or demo; a semantically invalid but well-formed model loads into the editor with the standing issues machinery visible (the always-valid-editor contract — parse accepts, the engine refuses, pinned).
- SCOPE LOCKS: the file carries no computed results; mode and mode payment are working state, not project data — a loaded project opens in mode A (disclosed); theme is a viewer preference and never persists; the demo and blank-start behaviors are unchanged.
- THE ENGINE IS UNTOUCHED: computeModel, validate, scenarios, financing, and every existing core pin are byte-identical; the file layer adds no computation (engine-blind).

## Chunk 0 — the core file format (core/src/fileio.ts, additive)

`core/src/fileio.ts` (new) and the `core/src/index.ts` export line:

- `FILE_KIND = "calcvibes-project"`; `FILE_VERSION = 1`; `ProjectFileError extends Error` (name "ProjectFileError").
- `type FileEntryUnit = "ones" | "thousands" | "millions"` (structurally identical to the web EntryUnit; the web maps freely, nothing re-exported).
- `interface ProjectFileSettings { startYear: number | null; entryUnit: FileEntryUnit; scenarioTargets: number[] | null; scenarioTerms: number[] | null; scenarioBalloons: number[] | null }`.
- `serializeProject(inputs, settings): string` — canonical JSON.stringify with two-space indent and a trailing newline, fixed key order (fileKind, fileVersion, project, settings); deterministic.
- `parseProject(text): { inputs, settings }` — the named refusals, every message pinned verbatim below. A missing optional field inside settings is not a refusal (null semantics); a present-but-wrong-typed one is.

## Chunk 1 — web save/load (web/src/projectFile.ts new; App.tsx header chrome)

- web/src/projectFile.ts: `projectFileName(projectName: string): string` — lowercase; keep [a-z0-9]; every other character becomes a dash; runs collapse to one; leading and trailing dashes trim; the empty result defaults to "project"; the extension is ".calcvibes.json". Pins: "Project Alpha" → "project-alpha.calcvibes.json"; "" → "project.calcvibes.json"; "Malmö Port 4!" → "malm-port-4.calcvibes.json". Plus `downloadProjectFile(inputs, settings)` — serializeProject and the browser download (the Blob + objectURL + click pattern of the XLSX route; the anchor carries the project file name and type "application/json").
- App header chrome: Open project (`data-testid="open-project"`, a hidden file input with accept ".calcvibes.json,.json") and Save project (`data-testid="save-project"`).
- OPEN: the change handler reads the file text, parseProject, and replaces the editor state — setInputs, setStartYear, setEntryUnit, setScenarioTargets, setScenarioTerms, setScenarioBalloons (the three carried items close here); the view stays; mode resets to A (disclosed convention of record). A refused open leaves the current project untouched.
- SAVE: serializeProject(inputs, the settings-from-state) and downloadProjectFile. SAVE IS ALWAYS ENABLED — the export disable-contract does not apply: saving an invalid-in-progress model is legitimate (the file is the editor state; the mid-edit rescue convention — the W4 story completes here: a crashing or lost session no longer loses the project). Disclosed convention of record.
- LOAD REFUSALS SURFACE VISIBLY: a banner under the header (`data-testid="load-error"`) carrying the exact ProjectFileError message; it clears on the next successful load or open and never blocks further work. No silent fallback: a refused open never swaps in the demo or blank project.
- Web pins (web/test/project-file.test.tsx): APP-CHROME (both buttons present; save enabled on the blank project and on an invalid model), OPEN-LOAD (loading the template project file text puts Project Alpha into the editor with the settings restored — the name input shows Project Alpha, the start year 2026, the entry unit ones, the scenario boxes [8, 10, 12] / [10, 15] / [0, 1000000]), SAVE-NAME (the three slug pins, the .calcvibes.json extension), LOAD-ERR (a malformed file surfaces the banner with the exact FILE-MALFORMED message and the current project untouched), SETTINGS-RESTORE (the three carried items restored from the file), NO-DEFAULT-DEMO (a refused open leaves the editor state byte-unchanged).
- The XLSX route, the PDF route, the deck, the presentation, and every standing web pin are untouched.
