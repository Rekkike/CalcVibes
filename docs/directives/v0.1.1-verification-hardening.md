## Task 1 — Validation contract

`validateInputs(inp): string[]` returns a list of human-readable issues; empty list means valid. Rules (each produces an issue naming the offending line by name and id, or the repayment block):

1. Cost line: non-empty name; amount greater than 0; startYear is an integer of at least 1; recurring lines have durationYears of at least 1; escalation is finite.
2. Repayment: termYears of at least 0; graceYears of at least 0; paymentsPerYear is one of 1, 2, 4, 12; paymentEscalation is finite; balloon of at least 0.
3. targetIrr greater than -100.
4. An empty cost list is valid (zero lines, solved payment zero, achieved IRR null — CP-4 behavior unchanged).

`computeModel` calls `validateInputs` first and throws `EngineInputError` (an Error subclass carrying the issues array) when any issue exists. The silent filter `c.name && c.amount > 0 && c.startYear >= 1` is removed; this is a deliberate, documented deviation from the prototype (spec 4.7). Tests: one per rule, each feeding a violating input and expecting the throw with the expected issue text; red proof per rule by observing the rule fire. Valid inputs from the v0.1 suite must produce no issues.

## Task 2 — Invariant tests (deterministic cross product)

Scenario family: the baseline cost lines from `core/test/engine.test.ts` crossed with targetIrr in {0, 12, 40}, graceYears in {0, 2}, termYears in {3, 10, 15}, paymentsPerYear in {1, 12}, paymentEscalation in {0, 3}, balloon in {0, 500000}. The full cross product is 144 cases; run all of them (pure and fast).

- INV-1 Solver identity: for every case, |NPV(inflows at target monthly rate) - costNpv| <= 1e-6 * costNpv. Compute NPV(inflows) from the returned monthly rows.
- INV-2 Achieved-IRR identity: for every case (all have a single sign change in the net vector), |achievedIrr - targetIrr| < 1e-9.
- INV-3 Scaling invariance: for the baseline case, multiply every cost amount and the balloon by k = 7.3; every monetary output scales by k within 1e-9 relative; achievedIrr and paybackYears are unchanged within 1e-12.
- INV-4 Determinism: two calls with identical inputs produce deeply equal results (JSON.stringify comparison).
- INV-5 No non-finite outputs: across all 144 cases plus the CP-4 empty-costs case, every numeric output is finite or null; NaN and Infinity are forbidden in any field, including monthly rows.
- INV-6 Aggregation identities: for every case, each yearly row's cost equals the sum of that year's monthly costs within 1e-9 relative; the final cumulative equals netGain within 0.01; monthly.length equals the structure implied by lastCostYear, grace, and term.
- INV-7 Monotonicity probes (baseline case): balloon 500000 yields a strictly smaller paymentAmount than balloon 0; graceYears 2 strictly smaller than 0; targetIrr 40 yields a strictly smaller costNpv than 12; termYears 15 yields a strictly smaller paymentAmount than 3.
- INV-8 Slot grid: paymentCount equals round(termYears * paymentsPerYear) clamped by the totalMonths bound; first slot at repaymentStartYear * 12.

## Task 3 — Sign-change counting and ambiguity flag

`countSignChanges(flows)`: counts sign changes across non-zero entries (zeros are skipped); returns 0 for an all-zero vector. `ModelResult` gains `signChanges` and `irrAmbiguous` (true when signChanges is greater than 1). Pins:

- countSignChanges([-1, -2, 3, 4]) = 1
- countSignChanges([-1, 2, -3]) = 2
- countSignChanges([0, 0, 0]) = 0
- countSignChanges([0, -5, 3, 0, 2, -1]) = 2
- Baseline CP-2 result: signChanges = 1, irrAmbiguous = false.

Red proof per pin by perturbation.
