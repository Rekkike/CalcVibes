## 3. Task A — the suggest affordance (the one-click derivation)

The settled ruling of record: NOT silent auto-population. The deck-omission contract and the
authored-state honesty stand — a project with no timeline block stays unauthored until the user
acts. The affordance is the only route from the cost program into the timeline.

- Seat: web/src/sections/TimelineSection.tsx, under the empty state (the timeline-empty
  paragraph, line 73 of the current tree). A button data-action="suggest-activities", labeled
  "Suggest activities from the cost program".
- Gating: the button is enabled only while the activities grid is empty; once any activity
  exists it is disabled, with a title attribute saying why (the suggestion is a starting
  draft, never a merge into authored work).
- The derivation contract (a pure helper suggestActivitiesFromCosts in web/src/state.ts,
  returning TimelineActivity[]):
  - One derived activity per cost line of inputs.costs. Operating lines are EXCLUDED (a
    separate block, an operating cost, not a program activity) — the exclusion is disclosed
    in the review note.
  - label: the cost line's name. ids: the shared nextId helper under the activity prefix (the
    same prefix the Add activity button uses).
  - A recurring line spans startYear..startYear + ceil(durationYears) − 1 (the ceil honors
    fractional durations; the engine charges a 2.5-year duration as three years — the AUD-40
    observation of record).
  - A capex line without yearOverrides is the lump year: startYear..startYear.
  - A capex line with yearOverrides spans min..max of the override-year keys (the per-year
    profile IS that line's program).
  - A recurring line's yearOverrides refine amounts within the nominal span, never extend it.
    HALT-AND-REPORT if the engine's profile convention contradicts this reading before
    landing.
  - phase: every derived entry enters as "production" — the phase is not derivable from a
    cost line. The review note discloses this.
  - No gates and no milestones are derived (the BP set is authored planning, not suggestion).
- The suggestion IS authorship: the one click commits the derived activities into the timeline
  block through the existing setTimeline seam — the authored state flips (timelineAuthored),
  and the deck Gantt composes subject to the standing refusal discipline. No preview step; no
  auto-populate on load or on fixture load.
- The review note: after a suggestion, the section renders a muted line
  (data-testid="timeline-suggestion-note") disclosing the derivation — the count, the
  operating-line exclusion, and the Production-phase default; the exact wording disclosed in
  the completion report.
- The empty-state re-anchor: the timeline-empty paragraph re-anchors to mention the
  affordance (the current text: "No timeline authored yet. Add an activity, a decision gate
  or a milestone to start; the deck shows a program Gantt slide once the timeline is authored
  and refusal-free." — extended with the suggestion; exact wording disclosed). The pin
  re-anchors with it.
- Pins and red proofs: the derivation pins cover each case — the recurring span, the capex
  lump year, the capex override min..max span, the operating exclusion, the empty-grid gating,
  the authored flip, the review note, the empty-state re-anchor. Red proof: a profile-bearing
  capex line deriving the lump year instead of the min..max span observes red, then green.
