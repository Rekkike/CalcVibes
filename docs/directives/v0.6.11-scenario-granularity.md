## The semantics of record (before the tasks)

THE OPTIONAL-REALITIES SEMANTICS (the user's ruling, walkthrough Round 46 Supplement 11): each scenario is an optional reality — it recomputes the model honestly under its own stated terms. The surface shows which realities are computable and which are not, the reason attached to each. No variant ever bends the underlying data to make itself renderable: a reality that cannot exist under its own terms is shown as exactly that. The declared tariff span is data; a variant whose terms push its required collections beyond that span is disclosed as the extension it is — never a silently extended grid, never an invented price, never a killed set. The wholesale refusal of the named set and the tornado (the v0.6.10 delivered behavior, superseded as a design of record by walkthrough Round 46 Supplement 5) is replaced by per-item honesty everywhere: per scenario on the named set, per cell on the tornado, per cell on the two-way tables (the Task D.2 precedent, now extended to the two remaining surfaces).

The economics of the underlying model are untouched by this pass. The golden battery stays byte-identical; the funding pins stay byte-identical; the two-way table values stay byte-identical; the deck's existing figures stay byte-identical, the scenario-delta items additive.

## Task A — the named set degrades per scenario (core/src/scenarios.ts)

scenarioResults returns a per-variant outcome record. The shape of record:

```ts
export type ScenarioOutcome = { result: ModelResult; refusal: null } | { result: null; refusal: string };
export function scenarioResults(inp: ModelInputs): Record<"base" | "optimistic" | "pessimistic", ScenarioOutcome>;
```

Each of the three variants is computed individually inside its own try/catch. The catch takes ONLY EngineInputError — any other throw propagates (the Task D.2 precedent; a genuine defect never masquerades as a refusal). The refusal is the caught error's message verbatim — the full sentence the engine throws, exactly the string the per-cell tables render today (including the "Invalid model inputs: " prefix). The scenario sets themselves (SCENARIO_SETS and applyScenario) are UNCHANGED.

## Task C — the span-coverage refusal carries its cause and its check (core/src/engine.ts)

The string today reads: `Tariff span does not cover the required collection stream: year ${slotYear} carries required collections outside the tariff grid.` It names the year but not the declared bounds, and it prescribes nothing. The string of record:

`The required collections extend to year ${slotYear}, beyond the declared tariff span (years ${gridFirst}-${gridLast}): widen the tariff span or shorten the term.`

gridFirst and gridLast are the actual grid bounds — gridYears[0] and gridYears[gridYears.length - 1] — never assumed constants; on the program fixture 3 and 23, the failing year 24. The diagnosis, the cause, and the check in one sentence, per the ambiguity-warning discipline of Round 46 Supplement 1. The old string is retired at every site; the funding0610 W35 string anchors re-anchor to the new sentence (disclosed in the ledger). The zero-weighted-volume refusal ("Grid year N has zero weighted volume against a positive required collection.") is UNCHANGED — a different refusal class, out of scope.
