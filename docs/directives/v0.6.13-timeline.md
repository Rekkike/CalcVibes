## 3. The timeline data model (the feature of record)

The project schema gains an optional timeline block on ModelInputs (core/src/types.ts):

- projectScale: "mini" | "full" (default "full").
- activities: { id, label, startYear, endYear, phase }[] — phase is one of "prestudy",
  "detail-design", "production" (the three phases of record); startYear and endYear are
  program-year integers (1-based, consistent with the engine's year indexing);
  startYear <= endYear.
- decisionPoints: { id, title, year, outcome? }[] — outcome is one of "continue",
  "change", "terminate" (the PPS fortlevnad vocabulary: fortsätta, förändra, lägga ner);
  an absent outcome means the gate is not yet held.
- milestones: { id, label, year, tie? }[] — zero-duration markers; the optional tie is
  { kind: "activity", activityId } or { kind: "engine-event", event }, the engine events
  of record being "construction-complete", "first-collection-year" and "funding-received".
- All four collections take their ids from the shared collision-proof helper of Task E.

The PPS-aligned decision-point vocabulary of record (the default titles, drawn from the
PPS BP set as sourced at the Swedish Wikipedia article on Praktisk Projektstyrning and
tietoevry.com, read 2026-10-20 and re-read 2026-10-21):

- BP1 — Beslut om att starta projektet och initiera förberedelserna
- BP2 — Beslut om att fortsätta, avbryta eller göra om förberedelsearbete
- BP3 — Beslut om att det finns tillräckligt bra underlag för att göra ett åtagande för
  resterande del av projektet
- BP4 — Beslut att starta genomförandet
- BP5 — Beslut om att fortsätta eller förändra projektåtagandet
- BP6 — Beslut om att godkänna leverans av projektets delresultat eller slutresultat
- BP7 — Beslut om att godkänna överlämning av ansvaret för projektets resultat till
  förvaltningen
- BP8 — Beslut om att avsluta projektet

- The "full" scale carries BP1 through BP8. The "mini" scale carries the condensed
  four-point set BP1, BP3, BP4, BP8 — all three phases covered, and the same validation
  and refusal discipline applied as strictly as the full set (the Round 49 ruling).
- The default titles are user-overridable labels; the BP codes always render with the
  title on the deck slide.
- The PPS disclosure of record renders once, muted, in the Timeline section: "The
  decision-point vocabulary is aligned with PPS (Praktisk Projektstyrning); this
  application does not implement or certify PPS." The application never claims to
  implement or certify PPS anywhere.
- The three phase names render as Prestudy, Detail design and Production; the phases and
  the gates are related per PPS in vocabulary only — the Gantt lanes are the three phases
  of record, and the gates are program-year events (no forced BP-to-phase mapping).

## 5. The refusal discipline (section-local, never compute-blocking)

The refusals compose in the Timeline section's own refusal panel, data-driven, in the
v0.6.11 wording pattern (cause and check in one sentence, the actual bounds carried):

- TIMELINE-ACTIVITY-SPAN: an activity outside the program span refuses, naming the
  activity and carrying the true span.
- TIMELINE-ACTIVITY-ORDER: startYear greater than endYear refuses.
- TIMELINE-GATE-SPAN: a decision point outside the program span refuses.
- TIMELINE-MILESTONE-SPAN: a milestone outside the program span refuses.
- TIMELINE-MILESTONE-TIE: a milestone tied to a non-existent activity refuses, naming
  the activities present; an engine-event tie whose event does not compose for this
  project (for example no funding block) refuses, naming the events available.
- The program span is the declared project length when declared, else the derived horizon
  — the same span the engine composes; every refusal names the true span (the AUD-4
