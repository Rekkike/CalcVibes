## 1. The request and the rulings of record

The user request: a button in the Timeline section that imports a Gantt PDF exported from another project application — selectable text, clear column fields, the Swedish headers aktivitet, startdatum, slutdatum, varaktighet — and composes the timeline activities from the rows. The rulings of record, given in the controller session (2026-11-09):

1. NO SAMPLE FILE — the real exports carry confidential content and will not be provided; the layout is described as basic and clear. The parser composes against the described layout, and every import discloses a parse report, so a layout mismatch surfaces honestly rather than becoming garbage rows.
2. PROGRESS DROPPED — a progress column, when present in the export, is ignored; no progress field enters the model.
3. YEAR-GRAINED — the export carries days and months (the parse aid); the import composes year-grained activities, the existing optional-month vocabulary untouched, absent fields the default.
4. REPLACE — an accepted import replaces the activities grid wholesale; the gates and the milestones untouched, the panel disclosing the replacement.
5. THE HEADERS OF RECORD — aktivitet, startdatum, slutdatum, varaktighet (lowercase in the export; the matching case-insensitive and whitespace-tolerant).

## 2. Tasks

Task A — the parser, web-side and additive: a client-side PDF text extraction through an additive web dependency (the application stays a client-side static site — no backend, no upload, no cloud). The parser reads the text items with their coordinates, locates the column headers by the words of record, and composes rows: the activity name, the startdatum, the slutdatum, the varaktighet. The dates parse in the standard numeric forms (ISO and the common European orderings, the Swedish month names accepted); the YEAR is the operative part, the days and months the parse aid, dropped at composition per the ruling. The varaktighet is a consistency check only: the parsed duration cross-checked against the start and the end, a mismatch disclosed in the parse report; the duration never overrides the dates. Every import produces the parse report — the rows found (name, start year, end year, the duration check), the rows refused with their cause, and the summary counts; never a silent partial import.

Task B — the year mapping and the phase: the calendar years map to program years through the project start year (the program year = calendar year − start year + 1); a row falling before the start year surfaces in the report, the mapping named in the panel. Every imported activity takes the production phase (the phase underivable from the export; the suggestion-affordance precedent; the phase editable after authoring).

Task C — the import button and the review step: a button in the Timeline section, the file chosen through the browser picker; the parse report panel composes as the disclosure. ACCEPT authors the parsed rows — the import IS authorship: the activities grid replaced wholesale, the gates and the milestones untouched, the authored rows falling under the standing refusal discipline (TIMELINE-ACTIVITY-SPAN, TIMELINE-ACTIVITY-ORDER), section-local, never compute-blocking. REFUSE leaves everything untouched, nothing written. No silent auto-population: nothing composes without the explicit accept.

Task D — the refusals, collect-all: the new TIMELINE-IMPORT family — the unparseable file (not a PDF), the headers unmatched (the words of record not found), the dates unparsed (the row refused with its cause), the zero-row parse (an empty export disclosed, never a silent no-op), the before-start-year row disclosed in the report. The existing validation untouched in its firing rules.

Task E — the fixture, the pins and the red proofs: a generated fixture PDF in the described basic layout (the four lowercase headers, rows carrying days and months) authored as a test fixture — a test artifact, never presented as a real export. The parser pinned against it: the columns located, the rows composed, the years mapped, the duration checked. The pins: the no-write pin (a refused import leaves the document byte-identical), the replace pin (an accepted import replaces the activities grid, the gates and the milestones untouched), the report pins (the unmatched headers, the unparsed dates, the duration mismatch, the before-start-year row, the zero-row parse), the authoring pin (the accepted rows authored, editable, saved and loaded). The red proofs per the standing discipline, each mutation observed red and restored hash-checked. No demo gains the import (the demo-honesty principle: the import is a user-driven affordance).
