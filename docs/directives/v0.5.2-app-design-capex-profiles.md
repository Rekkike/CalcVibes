# Directive v0.5.2 - Application design system and per-year cost profiles

Date: 2026-10-08. Vehicle for: the user's walkthrough findings at the live deployment, the five observations of record of v0.5.1, the ratification of the stylesheet hotfix, and the per-year override table of record (specification section 4.2, recorded at v0.1.0, never delivered).

## Preamble: findings of record

1. The main application views carry no styling. The v0.5.1 design system styles the presentation deck only: every deck rule in web/src/index.css is scoped under [data-testid="presentation"]. The user's verdict at the live walkthrough: the application looks atrocious, a far cry from the prototype. The prototype (prototype/standalone-prototype.html) remains the visual reference of record for the application views. This pass closes the gap: one design language across the entire application.
2. CAPEX lines lock the duration field. In the delivered model a CAPEX line is a single lump landing at one year (month 12 x startYear), so a multi-year, varying CAPEX program is inexpressible as one line. The user is right: real CAPEX runs over years and varies year by year (the user's example: 3 MSEK in 2025, 30 MSEK in 2026, 300 MSEK in 2027, 5 MSEK in 2028). The fix is the per-year override table of record, now extended by decision of record to CAPEX lines as a first-class per-year spend profile.
3. The user works from an iPhone at the live site. A responsive layout is a first-class requirement of this pass, not a polish item.

The aesthetic bar of record stands: the presentation layer rivals PWC/KPMG/McKinsey/BCG quality; design augments the truth, never displaces it. Every figure remains engine-emitted; no renderer computes a financial figure.

## Task B - Per-year cost profiles (engine + web)

Deliver yearOverrides: an optional map of model year to annual amount on any cost line. Conventions of record:
- CAPEX line with overrides: each year's amount lands as one lump at month 12 x year (the standing CAPEX convention); the line's span is the min..max of the override years; the amount/startYear/duration fields are inert while overrides are present; the lastCostYear contribution is the maximum override year (so a profile can move the repayment start, pinned).
- Recurring line with overrides: the year's amount replaces the computed amount x escalation for that year and spreads monthly like the line's other years; escalation does not apply to an overridden year (the override IS the amount); an override year outside the line's span is a surfaced input error naming the line and the year; overrides never move the repayment start.
- An override amount must be positive and finite; violations surface under the collect-all contract.
- Empty or absent overrides are byte-identical to current behavior. Every golden numeric pin unchanged. Schema v7 migration adds the optional yearOverrides field only; the template file gains no overrides.
- UI: the CAPEX line gains a per-year amounts editor (year and amount rows, add/remove); calendar-year labels through the shared header helper when settings.startYear is set (the engine never receives the start year); the amount label is corrected per kind (recurring: annual amount; single-year CAPEX: the lump; CAPEX profile: the editor); the duration field stays inert for CAPEX and the UI communicates why.

Pins (transcribed digit for digit from the verification script; the script re-validated against the golden anchors first: costNpv 6,632,597.98344, payment 475,309.13407, npvAtWacc 1,252,822.99465, PI 1.17913, all reproduced exactly):
- CAP-PROFILE: the template plus one CAPEX line with yearOverrides {1: 3,000,000; 2: 30,000,000; 3: 300,000,000; 4: 5,000,000}: totalCost 345,849,860.00; costNpv 249,938,650.47458; payment 20,060,600.48937; npvAtTarget within 1e-6 of zero; npvAtWacc 44,963,836.52290; PI 1.16214; firstPaymentMonth 48; paymentCount 28; lastPaymentMonth 129; horizon 132; yearly cost rows Y1 5,850,000.00 / Y2 32,466,000.00 / Y3 302,533,860.00 / Y4 5,000,000.00.
- CAP-IDENT (anti-double-count control): the same four lumps entered as four single-year CAPEX lines produce scalar-identical results (totalCost, costNpv, payment, npvAtWacc, and the full yearly table).
- OVR-REC: the template with c1 (Development team) yearOverrides {3: 2,000,000}: totalCost 7,940,240.00; costNpv 6,700,394.48742; payment 480,167.60698; year-3 cost 2,624,240.00 (the override replaces 1,909,620; escalation excluded); firstPaymentMonth 36 (unchanged).
- OVR-BYTE: an empty yearOverrides map is byte-identical to the untouched template (payment and costNpv equal to 1e-12).
- Directionals: overrides never move the repayment start (OVR-REC firstPaymentMonth 36); a CAPEX profile's maximum year does (CAP-PROFILE 48 vs the template's 36).
- Validation constructs: a recurring override outside the span surfaces an error naming the line and the year; a non-positive override amount surfaces an error.
